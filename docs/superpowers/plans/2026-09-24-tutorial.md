# Tutorial de controles — Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Un nivel de tutorial corto que se juega la primera vez (después de elegir personaje) y a
pedido desde el menú. Enseña a acelerar, frenar, cambiar de carril, saltar, usar pickups, el faro
y el disparo, y cierra con la horda. No se puede perder y se puede saltear.

**Architecture:** El tutorial corre como `GameScreen.Playing` con `GameFlow.EnTutorial`, sin
pantalla nueva. La lógica de pasos y recursos es C# plano testeado (`TutorialProgreso`,
`TutorialRecursos`). Un `TutorialDirector` en la escena `Tutorial.unity` aplica esa lógica: carteles,
recargas y control de la horda. El recorrido y la configuración propios salen de assets.

**Tech Stack:** Unity 6000.6, uGUI, Input System, NUnit EditMode, Unity CLI (skill
`driving-unity-editor`).

Spec: `docs/superpowers/specs/2026-09-24-tutorial-design.md`. Cada tarea lee el spec entero; este
plan no repite todos sus números.

## Global Constraints

- Proyecto `Juego/`, rama `Jose`. Unity se maneja con la skill `driving-unity-editor`
  (`.git/sdd/unity-context.md` lo resume). No usar herramientas `mcp__unity__*`.
- `Juego/Assets/_Zombineta/Simulacion` es compartida con `Prototipo/`: solo cambios aditivos. No
  cambiar reglas del juego.
- No se agrega un valor a `GameScreen`: el tutorial es `Playing` + `EnTutorial`.
- `GameSettings.TutorialVisto`: bool, clave `zombineta.tutorialSeen`, default false.
- Números del spec, literales:
  - condiciones de los pasos: turbo 1,5 s, marcha atrás 1 s, faro 2 s;
  - recorrido de 600 a 700 m, con objetos repetidos cada 30 a 40 m;
  - recursos: aviso por debajo del 20 %; en 0 se recarga al 60 %; la munición se recarga en 0
    durante los pasos 9 y 10;
  - horda: fija a 60 m detrás durante los pasos 1 a 9; al alcanzar en el paso 10 retrocede 35 m;
  - avisos 2,5 s; cartel final 2 s.
- Textos en castellano con tildes (la fuente del juego las muestra bien).
- Escenas, prefabs y assets se editan con comandos o con `eval` + `SerializedObject`, nunca a
  mano en YAML.
- Nada que mueva su transform va colgado del objeto `Nivel`.
- Nunca commitear `Juego/ProjectSettings/ProjectSettings.asset`. Commitear los `.meta` nuevos.
- Los commits terminan con `Co-Authored-By:` del modelo que los escribió.

### Task 2: Lógica pura de pasos y recursos

**Files (all new):**
- `Juego/Assets/_Zombineta/Scripts/Tutorial/TutorialPasos.cs` (ScriptableObject + `Paso` + enums)
- `Juego/Assets/_Zombineta/Scripts/Tutorial/TutorialProgreso.cs` (plain C#)
- `Juego/Assets/_Zombineta/Scripts/Tutorial/TutorialRecursos.cs` (plain C#)
- Test: `Juego/Assets/_Zombineta/Tests/Editor/TutorialLogicTests.cs`

All in `namespace Zombineta.Tutorial`.

**Interfaces (Produces):**
- `enum CondicionPaso { TurboSostenido, ReversaSostenida, CambioCarrilAmbos, Salto, PickupNafta, PickupBateria, PickupMunicion, FaroSostenido, DisparoAcertado, LlegarMeta }`
- `enum BarraHud { Ninguna, Nafta, Bateria, Municion, Amenaza }`
- `[Serializable] class Paso { [TextArea] string texto; CondicionPaso condicion; float cantidad; BarraHud resaltar; bool hordaSuelta; }`
  - `hordaSuelta` is false in steps 1–9 and true in 10: the director uses it to know when to release the horde.
- `TutorialPasos : ScriptableObject { List<Paso> pasos; }` with `CreateAssetMenu`.
- `sealed class TutorialProgreso`:
  - `TutorialProgreso(IReadOnlyList<Paso> pasos)`;
  - `int Indice`, `Paso Actual`, `bool Terminado`;
  - `bool Avanzar(in EntradaPaso e)`: consumes one frame and returns true if the step changed.
- `struct EntradaPaso { float dt; RunEvent eventos; DriveMode modo; bool faroPrendido; int deltaCarril; float nafta, bateria; int municion; float naftaPrevia, bateriaPrevia; int municionPrevia; bool meta; bool acierto; }`
  - `deltaCarril` is +1/−1 when the lane changed this frame.
  - `acierto` is true when a shot hit, meaning `Shot` without `ShotMissed`.
  - A pickup counts when `PickedUp` arrives and that resource went up compared with the previous value.
- `sealed class TutorialRecursos`:
  - `TutorialRecursos(float umbralAviso = 0.2f, float recarga = 0.6f)`;
  - `Decision Evaluar(float nafta01, float bateria01, int municion, bool recargaMunicion)`, returning:
    - `struct Decision { bool avisoNafta, avisoBateria, recargarNafta, recargarBateria, recargarMunicion; }`
  - `avisoX` goes true only once each time the resource drops below the threshold. It re-arms
    when the resource goes back above the threshold.
  - `recargarX` is true at 0. The director applies the recharge: `Recarga` × maximum.

- [ ] **Step 1: Failing tests**:
  - each condition advances with its correct input;
  - a step does not advance with another step's input; for example, a `PickedUp` of fuel during
    the battery step;
  - the timed conditions accumulate `dt` only while the action is held, and reset to 0 when it's
    released;
  - `CambioCarrilAmbos` needs one change up and one change down, in any order;
  - `Salto` needs `Launched` followed by `Landed`, or by `LandedPerfect`;
  - `DisparoAcertado` does not advance with `ShotMissed`;
  - `Terminado` is true after the last step;
  - `TutorialRecursos`:
    - warns once when the resource crosses 20 %;
    - doesn't warn again while it stays below;
    - re-arms above the threshold;
    - recharges at 0;
    - `recargarMunicion` only when `recargaMunicion` is true and the ammo is 0.
- [ ] **Step 2:** Watch them fail. **Step 3:** Implement. **Step 4:** Full suite green.
- [ ] **Step 5: Commit** with the message `Tutorial: logica pura de pasos y recursos`.

### Task 4: TutorialDirector y carteles

**Files:**
- Create: `Juego/Assets/_Zombineta/Scripts/Tutorial/TutorialDirector.cs` and `Juego/Assets/_Zombineta/Scripts/Tutorial/TutorialCartel.cs` (UI)
- Modify: `Tutorial.unity` (director on its own object; canvas with the step banner, warnings and highlight)
- Reuse: `ControlHints` and `InputDeviceTracker` to resolve `{Turbo}`, `{Reverse}`, `{LaneUp}`, `{LaneDown}`, `{Fire}`, `{Headlight}`. Check how `ControlHints` gets the binding per device and expose a function that returns the text for an action. Don't duplicate the table.

**Behaviour (spec §3–§6):**
- Each frame, the director builds `EntradaPaso` from `RunController` (intent, events of the step via `Stepped`, current and previous state) and calls `TutorialProgreso.Avanzar`. When the step changes, it shows the new banner with a fade.
- **Resources:** it applies `TutorialRecursos`:
  - warning in a small panel for 2.5 s;
  - recharge by writing `run.Sim.State.Fuel` / `Battery` / `Ammo`, with the text from spec §4. Read the maxima from `GameConfig` (`maxFuel`, `maxBattery`, `maxAmmo`; confirm the real names).
- **Horde:**
  - while `!Actual.hordaSuelta`: `Sim.Horde.Reset(PlayerX - 60)` + `State.HordeX = Sim.Horde.FrontX` every frame;
  - with `hordaSuelta`: if `Phase == Lost && Loss == CaughtByHorde`, it goes back to `Running`, resets the horde to `PlayerX - 35`, and shows "¡Te alcanzaron! Dispará o usá el faro".
  - Fuel at 0 must never end in Lost: the recharge comes first. If the simulation has a "no fuel" loss, check the `LossReason` values and handle them the same way.
- **HUD highlight:** a blinking frame over the bar for `Actual.resaltar`. Look up the HUD bar RectTransforms in `HudView` and expose read-only accessors if needed.
- **Final step:** the win is handled by `LevelFlowBridge` (task 1). The director shows "¡Listo! Ya sabés jugar" when it sees `Phase == Won` before the flow changes. If the bridge's victory shot is shorter than 2 s, add a wait to the bridge so the banner can be read.
- **UI:** readable over the scenery (semi-transparent background + `Outline`). Use the game's font and style.
